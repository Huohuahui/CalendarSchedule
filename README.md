# 加班 / 休息标记日历

一个纯静态、零依赖、可离线运行的排班日历 Web 应用。用于标记每一天的「加班」或「休息」，并附带农历、节日、月度目标进度、倒计时、天气、主题切换等实用功能。所有数据保存在浏览器本地，不依赖任何后端服务。

## ✨ 功能特性

- **排班标记**：点击日期即可标记「🌙 加班」/「☀️ 休息」，再次点击取消。
- **拖拽批量标记**：把底部「加班 / 休息」按钮拖到日期格子上即可完成标记；也支持「☑️ 多选」逐格勾选后批量标记。
- **撤销 / 重做**：所有排班变更自动记录历史，`Ctrl+Z` 撤销、`Ctrl+Shift+Z` 重做。
- **农历与节日**：基于 `lunar-javascript` 天文算法库实时推算农历日期与 24 节气（非查表，跨年无误差）；仅显示白名单内的法定与传统节日，界面清爽不拥挤。
- **月度目标进度**：「🎯 基础目标」与「⭐ 额外加班」双进度条，实时统计本月加班 / 休息天数。
- **可定制排班方案（🧭）**：目标天数不再是写死的「大月 15 / 小月 14」，任何人都能改成自己的规矩。
  - 点左栏「🧭 方案」入口打开设置：分别填**大月基础目标 / 小月基础目标 / 额外加班上限**；
  - 内置 **5 套行业预设**（标准班 / 双休制 / 大小周 / 上六休一 / 做一休一），也能把当前设置**存为「我的预设」**随时一键切换；
  - **生效时间三选**：仅本月（只影响这一个月）/ 从本月起（本月及以后）/ 指定月份（未来 12 个月内挑一个月开始）；
  - 改规则**不会污染历史月份**——之前的月份保留旧目标，达标统计不变；
  - 方案还带**配套排班模板**（如选了「双休制」自动推荐「仅工作日」），套用模板弹窗会把推荐项置顶并标注。
- **倒计时**：自定义添加任意目标日期，自动显示剩余天数。
- **待办事项**：点右侧「📝 待办」打开总览弹窗，在一处集中管理所有事项（不局限某一天）。支持新增 / 编辑 / 删除、勾选完成、按时间排序、逾期与今日高亮，以及「全部 / 待办 / 已完成」筛选；填写的「时间 + 主题 + 具体事宜」结构清晰，侧栏卡片实时显示待办数量。
- **临近提醒**：事项临近时用右下角悬浮卡提醒，多个事项自动合并成一张卡，可一键「✓ 完成」。提醒次数**按天累计封顶**：当天到期每天最多 5 次、明天到期每天最多 3 次、2~3 天内每天最多 1 次；触发时机为刷新页面、切回标签页、页面停留时每 30 分钟检查一次。
- **快速操作（2×2 宫格）**：待办事项、清空本月、套用模板、复制上月排班（「回到今天」按钮仍保留在日历顶部）。
- **排班模板**：内置「上五休二 / 上六休一 / 隔天轮换 / 仅工作日」等模板，一键套用。
- **天气 / 问候 / 时钟**：右侧面板展示今日天气（当前天气 + 关键时段 + 未来 6 天）、时段问候语与实时时钟。
- **自动定位 / 切换城市**：天气地点不再写死。首次打开先弹「定位说明卡」（讲清仅用于天气、坐标只存本机），点「允许定位」后浏览器才弹权限框；拒绝、失败或 `file://` 打开时自动回退到内置常用城市（默认汕头），不会白屏。天气标题显示当前城市，点击即可在弹窗里「使用我的当前位置 / 搜索任意城市 / 常用城市一键切换」。坐标只保存在本机浏览器。
- **主题切换**：多套主题配色，通过圆点一键切换。
- **备份中心（💾 备份）**：把备份能力集中到一处，并帮你记住「上次备份时间」。
  - **状态可视**：明确显示距上次备份多久、备份后是否又改过、当前数据量；
  - **到期提醒**：有未备份的改动且距上次备份 ≥ 14 天时，每天最多轻提醒一次（页脚入口显示红点）；
  - **三种搬运方式**：`导出文件`（JSON）、`复制备份文本`（粘贴到聊天/备忘即可跨设备搬运）、`粘贴文本导入`，另有 `选择文件导入`。
- **数据导入 / 导出**：备份内容为排班 + 倒计时 + 待办 + 排班方案 + 主题（`version: 4`），旧版备份（纯 map / `version: 2~3`）仍可正常导入。
- **☁️ 云备份（可选，默认关闭）**：开启后数据备份到**你自己的账号**下，换设备或清过缓存也能恢复。按账号隔离，别人看不到你的数据；恢复会用云端快照整包覆盖本机（有二次确认）。需**邮箱登录**，且仅在本应用的正式发布域名下可用 —— 本地打开或 GitHub Pages 预览环境会自动识别并提示，改用上面的本地备份。
- **关于页与隐私政策**：日历盒子**底部的页脚信息**（「排班日历 v1.0 · MIT 开源许可」+「关于 · 隐私政策」入口）。关于页含功能一览、数据与隐私摘要、**使用统计**、反馈渠道与开源许可；隐私政策逐项列出本机保存的每个键、会向哪些第三方发请求、权限用途，以及**如何撤回授权与彻底删除数据**的具体步骤。
- **使用统计（两级，分开控制）**：本地统计默认开启、只存本机（**仅记录事件名称与次数，不记录待办内容、排班日期、城市或坐标**）；匿名上报默认关闭，且需运营者配置上报地址后才可能生效——两条任一不满足就不发任何请求。
- **本地错误日志**：页面出 JS 报错时记下最近 10 条（信息 / 位置 / 堆栈，均截断），在关于页可查看、一键复制成报告或清除。**只存本机、不自动上传**，也不含你的排班或待办内容。
- **键盘无障碍**：日历支持方向键移动、`Home`/`End` 跳月首月末、`Enter`/空格切换状态；整月采用 roving tabindex，`Tab` 只需按一次。所有弹窗统一支持 `Esc` 由上层到底层逐级关闭。
- **PWA 离线**：通过 Service Worker 缓存资源，首次加载后可离线使用，支持「添加到主屏幕」。

## 🧩 技术栈

- 原生 HTML + CSS + JavaScript（**无构建流程、无框架、无第三方 CDN 依赖**）
- 农历计算：`js/lunar.min.js`（[lunar-javascript](https://github.com/6tail/lunar-javascript) v1.6.11）
- 数据持久化：浏览器 `localStorage`
- 离线能力：Service Worker（`sw.js`）+ Web App Manifest（`pwa/manifest.json`）

## 🚀 快速开始

### 本地打开
直接用浏览器打开 `index.html` 即可使用（推荐 Chrome / Edge / Firefox / Safari 等现代浏览器）。

> 提示：日历数据保存在当前浏览器的 `localStorage` 中。更换浏览器或清除浏览器数据会丢失标记，建议定期使用底部「💾 导出」备份。

### 部署到静态托管（如 GitHub Pages）
项目为纯静态文件，将整个目录推送到仓库并开启 Pages 即可：

```bash
git init -b main
git add .
git commit -m "init calendar schedule"
git remote add origin <你的仓库地址>
git push -u origin main
```

开启 GitHub Pages（Source 选择 `main` 分支根目录）后，访问分配的地址即可在线使用。

## 📝 数据说明

- 所有排班、倒计时、待办事项、排班方案、主题等数据均存于浏览器 `localStorage`，**默认不上传任何服务器**。
- 另有 `backupMeta`（上次备份时间与数据指纹）与 `cloudBackupEnabled`（云备份开关）两个辅助键；`weatherLocation` 存天气地点。
- 隐私模式或存储配额已满时，写入会失败并静默降级（不影响浏览）。
- 跨设备 / 跨浏览器同步：优先用「💾 备份 → 复制备份文本 / 导出文件」；或主动开启云备份（见下节）。

## ☁️ 云备份与账号

- **默认关闭**：不开启就不会加载云 SDK、也不会发出任何相关网络请求，保持「纯本地」的默认状态。
- **必须登录**：平台强制「用户数据按用户隔离」（行级安全策略 `owner_id = auth.uid()`），没有真实身份就无法安全存取，因此**不做匿名 / 设备号方案**。Web 端支持**邮箱**登录：密码登录、邮箱验证码登录/注册（新账号需设置密码）、忘记密码。
- **只在正式发布域名下可用**：服务端按请求来源域名（Origin）精确校验。本地 `file://`、GitHub Pages、各类静态托管预览环境都会登录失败 —— 程序会**提前识别并给出说明**，引导你改用本地备份，而不会伪造一个假的「云备份」。
- **不做字段级合并**：只上传整包快照，恢复时整包覆盖（有二次确认）。实现简单、行为可预期；代价是不能自动融合两台设备上不同日期的改动。
- **数据归属**：云端只保存你这一份快照，按账号隔离；换个账号登录看不到上一个账号的数据。

## 🧭 排班方案与目标规则

- 目标天数存在 `localStorage` 的 `schedulePlan` 键里，结构为：当前方案 `planId` + 配套模板 `templateId` + 自建预设 `customPresets` + 生效规则 `rules`（按 `from` 月份排序）+ 单月覆盖 `overrides`。
- **求值优先级**：某月单独覆盖 > `rules` 中「`from` ≤ 目标月」的最后一条 > 默认（大月 15 / 小月 14 / 额外 8）。
- 因此「从本月起生效」会清掉该月及以后的旧规则、保留更早的规则；「仅本月」只写一条单月覆盖，两者都不会改动历史月份的统计口径。
- 要调整内置预设，改 `js/plan.js` 的 `BUILTIN_PLANS` 数组即可（每项含 `bigBase` / `smallBase` / `extra` / `templateId`）。
- 单个数值有效范围 0–31，导入备份时会做清洗与上限截断，避免脏数据写坏界面。

## 📍 天气地点与隐私

- **自动定位需用户授权**：首次打开会先展示本站自己的「定位说明卡」，写明**仅用于获取天气所属城市**、坐标只存本机、会发给 open-meteo；点「允许定位」后才去请求浏览器权限。浏览器原生的权限弹窗由浏览器渲染，网页无法修改其文字（只能显示本站域名），因此说明卡是我们唯一能补充说明的地方。
- **必须 HTTPS**：GitHub Pages 是 HTTPS，定位可用；本地以 `file://` 双击打开的页面浏览器会禁用定位，此时自动回退到手动选城市。
- **坐标去向**：坐标只写入本机 `localStorage`（键名 `weatherLocation`），本项目没有服务器；天气请求会带坐标发给第三方 `open-meteo`。手动选择城市时发送的是城市中心坐标，而非精确位置。
- **搜索盲区**：在线地理编码对个别中文名不敏感（如「汕头 / 潮州 / 揭阳」需输入拼音 `shantou`）。因此程序内置了 100+ 常用城市，中文名可直接本地匹配，离线也能选。

## 🌗 农历与节日

- 农历与节气由算法库实时推算，覆盖 1900–2100 年，无需更新数据文件。
- 节日采用白名单机制（法定节日 + 传统节日），如需增删节日，修改 `js/calendar.js` 中的 `FESTIVAL_WHITELIST` 数组即可。
