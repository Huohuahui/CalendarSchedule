# 冒烟测试

本目录放的是**整站体检**脚本：起一个本地静态服务，用 [jsdom](https://github.com/jsdom/jsdom)
把真实页面连同真实脚本一起跑起来，然后在真实 DOM 上断言行为。

它不是单元测试，目的只有一个：**改动之后，确认整个应用还能正常跑起来**。

## 为什么要有它

本项目是纯静态、无构建的。以前每次改完都靠临时脚本手动验证、用完就删，
改动一多就完全没有回归保障 —— 页面白屏、弹窗打不开这类问题只能靠人肉点。

把验证固化下来之后，重构才有底气（尤其是"全局命名空间"和"代码风格统一"
这类大范围改动）。

## 怎么跑

```bash
cd 项目根目录
npm i jsdom            # 只是开发依赖；应用本身依然零依赖、无构建
node tests/smoke.js
```

退出码 `0` 表示全部通过，非 `0` 表示有失败项（失败项会列在末尾）。

jsdom 只装在本地 `node_modules/`（已被 `.gitignore` 忽略），
**不会进入发布产物，也不影响"打开网页即用"的定位**。

## 覆盖范围

| 小节 | 内容 |
|---|---|
| A | 主页加载、SEO 元信息、JSON-LD |
| B | 排班核心：标记 / 撤销 / 重做 / 进度 |
| C | 日历键盘可达性：role、roving tabindex、方向键、Enter 切换 |
| D | Esc 统一浮层管理（含多浮层优先级） |
| E | 备份中心：状态判定、指纹、导入校验 |
| F | 主题变量（确认品牌色没有写死在 JS 里） |
| G | 本地使用统计（含"未配置端点时绝不上报"） |
| H | 本地错误日志：去重计数、截断、报告文本、清空 |
| I | 关于页：统计渲染、错误列表、上报开关、反馈与许可 |
| J | 隐私政策：必备条款、存储键清单、无占位符 |
| K | 静态文件与配置：SW 版本与预缓存、robots、LICENSE、死代码已清 |

## 加功能时

在对应小节补几条断言即可。几个现成的模式：

- **断言运行期无报错**：主页跑完后 `errorLogSummary().count === 0`。
  这条最有用 —— 它同时覆盖了脚本报错和 Promise 拒绝。
- **断言不写死颜色**：读源码字符串检查（见 F 节）。
- **断言死代码已清**：同样读源码检查（见 K 节）。

## 已知边界

- jsdom 不执行 Service Worker、不做真实网络请求（测试里 `fetch` 被替换为拒绝），
  所以**天气、定位、云备份这些依赖网络与浏览器权限的路径不会被真实验证**。
  云备份需要在应用注册的正式域名下才能登录，无法在测试里覆盖。
- CSS 变量只在真实浏览器里参与计算，测试只能确认"引用的是变量"而不是"颜色显示正确"。
  视觉改动仍需人工看一眼。
